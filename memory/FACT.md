# RemindAI 项目知识

## 上下文压缩系统

### 当前配置（已实现方案 A + 输出预留）

#### 触发阈值
- **公式**: `(contextWindow - maxOutputTokens) * ratio`
- **输出预留**: 12.8K tokens (约 9600 个中文字)
- **默认比例**: 60% 可用输入空间
- **gpt-5**: 50% 可用输入空间（提前触发）

#### 保留策略（Token 预算驱动 + 轮数下限）
- **主标准**: Token 预算 = 可用输入空间 * 25%
- **软上限**: Token 预算 * 1.5 = 37.5%
- **辅助标准**: 至少保留 2 轮对话
- **选择**: 取两者中更保守的（保留更多）

#### 示例计算（128K 上下文）
```
可用输入: 128K - 12.8K = 115.2K
触发阈值: 115.2K * 0.60 = 69.1K (约 54% 总上下文)
Token预算: 115.2K * 0.25 = 28.8K
软上限: 28.8K * 1.5 = 43.2K

压缩后: 28.8-43.2K (25-37.5% 可用输入)
剩余空间: 71.9-86.4K (足够输出 + 多轮对话)
```

#### 位置
- `lib/core/agent/transformers/context_compactor.dart`
- `lib/core/toolshell/agent_loop.dart`（兜底逻辑）

### 已知问题与修复

1. **工具调用丢失（已修复）**
   - 旧逻辑删除整个 assistant 消息导致 "No tool output found" 错误
   - 新逻辑只移除孤立的 tool_calls，保留消息本身
   - 参考 Hermes 的 `_sanitize_tool_pairs` 实现

2. **压缩后仍超阈值（已添加验证）**
   - 预检：压缩前检查保真区大小
   - 后验：压缩后验证是否仍超阈值
   - 记录警告日志，建议调整策略

3. **保留区过大导致频繁压缩（已修复）**
   - 旧方案：固定保留 4 轮，可能导致压缩后仍超限
   - 新方案：Token 预算驱动，压缩后空间可预测
   - 输出预留：避免 LLM 输出时溢出

### 三家压缩策略对比

| 方案 | 触发机制 | 保留策略 | 优点 | 缺点 |
|------|---------|---------|------|------|
| **RemindAI（新）** | 60% 可用输入 + 输出预留 | Token预算 25% + 轮数下限 2 | 可预测、避免溢出、兼容现有架构 | - |
| **Hermes** | Token估算超阈值 | Token预算 20% + 轮数下限 3 | 全面控制、信息保留丰富 | 代码复杂（4600行） |
| **Cherry Studio** | Claude SDK 自动 | SDK 控制 | 简单、零维护 | 仅支持 Claude |
| **LangChain** | AI 工具调用 + 85% 兜底 | 保留 10% 上下文 | 智能时机选择 | 依赖 AI 推理、不保证及时 |

### 摘要生成策略
- **方式**: LLM 单次总结（不是 Agent 工具循环）
- **优化**: Cache-Aligned 复用原始消息前缀，95%+ 缓存命中
- **长度**: 400-600 字
- **内容**: 关键信息、技术细节、进度状态
